# Form interaction human review

Use `pass`, `needs revision`, `blocked`, or `not applicable`.

| Check | Status | Evidence / revision |
| --- | --- | --- |
| Every field has a visible label, purpose, instructions, native semantics, and correct input metadata. |  |  |
| Validation timing helps rather than punishes the user, and errors are programmatically associated. |  |  |
| Input is retained across known server, network, auth, conflict, and unknown failures. |  |  |
| Multi-step progress, drafts, back, resume, cancel, and final review behavior is explicit. |  |  |
| Pending, duplicate submission, timeout, uncertain outcome, retry, rollback, and success are defined from contracts. |  |  |
| Autofill, paste, password managers, localization, mobile keyboards, uploads, and long content are covered. |  |  |
| Keyboard, focus, announcements, summaries, touch, and custom-widget alternatives have evidence. |  |  |
