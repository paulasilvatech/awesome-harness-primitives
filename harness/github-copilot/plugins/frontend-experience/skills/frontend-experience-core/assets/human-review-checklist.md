# Frontend experience human review

Use one status per item: `pass`, `needs revision`, `blocked`, or `not applicable`.

| Area | Review question | Status | Evidence / required revision |
| --- | --- | --- | --- |
| Evidence | Are user, job, product language, data, states, system, and surfaces grounded in approved evidence? |  |  |
| Specificity | Could this experience only plausibly belong to this product and workflow? |  |  |
| Hierarchy | Does visual and interaction priority follow the real decision sequence? |  |  |
| Completeness | Are visible controls and applicable states implemented? |  |  |
| Adaptation | Do supported viewports, inputs, platforms, locale, zoom, and motion preferences change behavior appropriately? |  |  |
| Integrity | Are local tokens and components reused without an unjustified parallel system? |  |  |
| Traceability | Do acceptance IDs map to executed or documented manual evidence? |  |  |

Any `blocked` item blocks completion. `Needs revision` requires an owner and retest condition.
