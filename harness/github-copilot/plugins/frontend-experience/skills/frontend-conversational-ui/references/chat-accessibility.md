# Chat accessibility

- Use semantic regions and headings so conversation, composer, tools, citations, and status are navigable.
- Keep focus in the user's current context unless an error summary or approved flow requires movement.
- Announce message completion or meaningful phase changes, not every token.
- Provide pause, stop, or reduced-update behavior for frequent live changes.
- Keep the composer reachable with keyboard and screen reader without forcing users through the entire history.
- Ensure code blocks, tables, citations, attachments, and action menus have names, structure, and keyboard operation.
- Preserve text selection and reading during streaming.
- Restore focus after dialogs, tool approvals, attachments, and destructive confirmations.
