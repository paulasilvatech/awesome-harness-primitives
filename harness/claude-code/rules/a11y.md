# Accessibility Conventions — WCAG 2.2 AA Web Interfaces

These instructions apply to web UI, styles, and client-side framework code in HTML, CSS, JavaScript, TypeScript, React, Next.js, Angular, Vue, Svelte, and Astro files. They are authoritative for WCAG 2.2 AA accessibility, semantic HTML, ARIA, keyboard operation, focus management, forms, contrast, media alternatives, route announcements, and framework-specific accessibility fixes in matched files; stricter product, legal, design-system, or component-library accessibility rules win when they set a higher bar.

## Accessibility Target and Severity

Target WCAG 2.2 AA. It covers current legal requirements because it is a superset of WCAG 2.1 AA and WCAG 2.0 AA; WCAG 3.0 remains a Working Draft and is not a standard. Use severity to decide merge readiness.

| Severity | Meaning | Merge expectation |
| --- | --- | --- |
| CRITICAL | Users cannot access content at all. | Fix before merge. |
| IMPORTANT | Significant barrier for assistive technology users. | Fix in the same sprint or before release. |
| SUGGESTION | Improves usability for assistive technology users. | Plan deliberately; do not ignore. |

Legal context matters: the European Accessibility Act has applied since June 2025 across EU member states and references EN 301 549; ADA Title II digital accessibility deadlines begin April 2026 for larger US state and local governments and April 2027 for smaller entities; Section 508 references WCAG 2.0 AA with refreshes expected.

## Five Rules of ARIA

| Rule | Convention |
| --- | --- |
| Prefer native HTML | Use `<button>`, `<nav>`, `<table>`, `<label>`, and other semantic elements before ARIA because native semantics include keyboard and focus behavior. |
| Do not change native semantics where prohibited | Do not add incompatible roles such as `role="heading"` to a `<button>`. |
| Make ARIA controls keyboard operable | If `role="button"` is unavoidable, add focusability and Enter/Space handling. |
| Do not hide focusable elements from assistive technology | Never put focusable controls inside `aria-hidden="true"` content or set `aria-hidden="true"` on focusable elements. |
| Give every interactive element an accessible name | Use visible text, `<label>`, `aria-label`, or `aria-labelledby`. |

## Semantic HTML Anti-Patterns

| ID | Severity | Detection | Rule and fix |
| --- | --- | --- | --- |
| S1 Missing `lang` Attribute on `<html>` | CRITICAL | `<html` without `lang=` | Set `<html lang="en">`; in Next.js use `app/layout.tsx`, in Angular use `src/index.html`, and in Vue/Nuxt use `app.vue` or `nuxt.config`. |
| S2 Multiple `<h1>` Per Page | SUGGESTION | Multiple `<h1>` elements with unclear structure | Prefer one page-topic `<h1>` and use `<h2>` for sections. |
| S3 Heading Level Gaps | IMPORTANT | `<h1>` followed by `<h3>` | Keep logical heading order such as `h1 > h2 > h3 > h4`; style with CSS instead of skipping levels. |
| S4 Div Soup | IMPORTANT | Pages using only `<div>` without `<nav>`, `<main>`, `<header>`, `<footer>` | Use landmarks such as `<header>`, `<nav aria-label="Main">`, `<main>`, and `<footer>`. |
| S5 Layout Tables Without `role="presentation"` | IMPORTANT | `<table>` without `<th>`, `<caption>`, or `role="presentation"` | Use CSS Grid or Flexbox; if layout table is unavoidable, add `role="presentation"`. |
| S6 Data Tables Without Headers | CRITICAL | Data rows without `<th>` | Add `<caption>`, `<thead>`, `<th scope="col">`, and structured `<tbody>`. |
| S7 Non-Descriptive Link Text | IMPORTANT | `click here`, `read more`, `learn more`, `here`, `more`, or `link` | Write purpose-revealing text such as `View pricing plans`. |
| S8 Interactive Elements Without Semantic HTML | CRITICAL | `<div.*(?:onClick|@click|\(click\))` | Use `<button>` instead of click handlers on generic elements. |

## ARIA Anti-Patterns

| ID | Severity | Detection | Rule and fix |
| --- | --- | --- | --- |
| A1 Redundant ARIA on Native Elements | SUGGESTION | `<button.*role="button"`, `<nav.*role="navigation"`, `<a.*role="link"` | Remove redundant ARIA. |
| A2 `aria-hidden="true"` on Focusable Element | CRITICAL | `aria-hidden="true"` on button, input, anchor, or `[tabindex]` | Use `disabled` for native controls, remove `href` or `tabindex`, use `inert`, `hidden`, or remove the content from the DOM. |
| A3 Missing Required ARIA Properties | CRITICAL | `role="tab"` without `aria-selected`; `role="checkbox"` without `aria-checked` | Add required properties: `tab` needs `aria-selected`, `combobox` needs `aria-expanded` and `aria-controls`, `slider` needs `aria-valuemin`, `aria-valuemax`, and `aria-valuenow`, and `checkbox` needs `aria-checked`. |
| A4 Invalid ARIA Role Values | CRITICAL | `role="[^"]*"` with non-existent values | Avoid invalid roles such as `role="input"`, `role="text"`, or misspellings. |
| A5 ARIA Where Native HTML Works | IMPORTANT | `role="button"` or `role="checkbox"` on `<div>` | Replace with native `<button>` or `<label><input type="checkbox" /> Accept terms</label>`. |
| A6 Missing `aria-label` on Icon-Only Buttons | CRITICAL | Icon-only `<button>` with SVG and no text or `aria-label` | Add `aria-label="Close dialog"` and mark decorative SVGs `aria-hidden="true"`. |
| A7 `role="presentation"` on Focusable Elements | IMPORTANT | Presentation role on interactive elements | Remove the role because browsers ignore it on focusable elements. |
| A8 Missing Live Region for Dynamic Content | IMPORTANT | Toasts or notifications without `role="alert"`, `role="status"`, or `aria-live` | Use a preexisting live region such as `role="status" aria-live="polite"`; use `role="alert"` for errors. |

## Keyboard and Focus Anti-Patterns

| ID | Severity | Detection | Rule and fix |
| --- | --- | --- | --- |
| K1 `onClick` Without `onKeyDown` on Non-Native Elements | CRITICAL | `(?:onClick|@click|\(click\))` on `<div>` or `<span>` without keyboard handler | Use `<button>`; if impossible, add `role="button"`, `tabIndex={0}`, and Enter/Space handling. |
| K2 Positive `tabindex` Values | CRITICAL | `tabindex="[1-9]\d*"` or `tabIndex={[1-9]\d*}` | Use only `tabindex="0"` for tab order and `tabindex="-1"` for programmatic focus. |
| K3 Focus Trap Without Escape | CRITICAL | Modal or overlay without Escape handling or focus trapping | Prefer native `<dialog>` with `showModal()`; otherwise trap Tab, use `inert` outside the dialog, dismiss on Escape, and return focus. |
| K4 Missing Skip Link | IMPORTANT | No skip link as first focusable element | Add `<a href="#main-content" class="skip-link">Skip to main content</a>` and `<main id="main-content" tabindex="-1">`. |
| K5 `outline: none` Without Replacement | CRITICAL | `outline:\s*none` or `outline:\s*0\b` without replacement | Provide `:focus-visible` styles such as `outline: 2px solid #005fcc; outline-offset: 2px;`. |
| K6 Mouse-Only Interactions | IMPORTANT | `onMouseOver`, `onMouseEnter`, or `@mouseenter` without keyboard equivalent | Pair hover with `onFocus`/`onBlur` and `onMouseEnter`/`onMouseLeave`. |
| K7 Focus Not Returned After Custom Modal Close | IMPORTANT | Custom modal close without focus restoration | Store `triggerElement` or a logical fallback and call `triggerElement.focus()`. |

## Form Anti-Patterns

| ID | Severity | Detection | Rule and fix |
| --- | --- | --- | --- |
| F1 Input Without Associated Label | CRITICAL | `<input`, `<select`, or `<textarea` without `<label>`, `aria-label`, or `aria-labelledby` | Associate a visible label, for example `<label for="email">Email address</label><input id="email" type="email" />`. |
| F2 Error Messages Not Linked to Input | CRITICAL | Error near input without `aria-describedby` | Set `aria-invalid="true"` and link `aria-describedby="email-error"`. |
| F3 Required Field Indicated Only by Color or `*` | IMPORTANT | `required` or `*` without `aria-required="true"` or HTML `required` | Use HTML `required` and a text note such as `Fields marked * are required`. |
| F4 No Error Summary or Focus on First Error | IMPORTANT | Submit handler without validation focus management | Focus the first invalid field or a focusable error summary. |
| F5 CAPTCHA Without Accessible Alternative | IMPORTANT | Puzzle or image CAPTCHA without fallback; password field with `autocomplete='off'` or paste-blocking JavaScript | Use accessible alternatives such as reCAPTCHA v3 or hCaptcha accessibility mode; never block paste or autofill on passwords. |
| F6 Placeholder as Label | IMPORTANT | `placeholder=` without a real label | Use placeholder only as a hint and pair it with a visible label. |

## Visual, Color, Motion, and Media Anti-Patterns

| ID | Severity | Detection | Rule and fix |
| --- | --- | --- | --- |
| V1 Insufficient Text Contrast | CRITICAL | Normal text below 4.5:1 or large text below 3:1 | Use compliant color pairs, for example avoid `#999` on `#fff` and prefer stronger contrast such as `#595959` on `#fff`. |
| V2 Information Conveyed by Color Alone | CRITICAL | Error or success distinguished only by color | Add text, icon, pattern, underline, or border. |
| V3 Fixed Font Sizes Preventing Resize | IMPORTANT | `font-size:\s*[0-9]*px` outside root/base | Use `rem` or `em` for content fonts. |
| V4 Content Not Reflowing at 320px | IMPORTANT | Fixed-width containers or horizontal scroll | Use responsive Grid or Flexbox and test at 320px CSS width. |
| V5 Animation Without `prefers-reduced-motion` | SUGGESTION | `animation:` or `transition:` without media query | Gate non-essential animation behind `@media (prefers-reduced-motion: no-preference)`. |
| D1 Informational Image Without Alt Text | CRITICAL | `<img` or `<Image` without `alt=` | Use descriptive alt text; decorative images use `alt=""`. |
| D2 Decorative Image with Non-Empty Alt | SUGGESTION | Decorative image with meaningful alt | Use `alt=""` and `aria-hidden="true"` for decorative SVGs. |
| D3 Video Without Captions | CRITICAL | `<video` without `<track kind="captions">` | Add captions such as `<track kind="captions" src="/tutorial-en.vtt" srclang="en" label="English" default />`. |
| D4 Audio/Video Autoplay | IMPORTANT | `autoplay` without `muted` | Never autoplay audio; if video autoplays, start muted with controls. |

## Framework-Specific Conventions

| ID | Framework | Rule |
| --- | --- | --- |
| RX1 | React / Next.js | Use `htmlFor` instead of `for` in JSX labels. |
| RX2 | React / Next.js | Manage SPA route changes with focus management or live regions; Next.js route announcer reads `document.title`, then `<h1>`, then pathname, so each page needs a unique `<title>`. |
| RX3 | React / Next.js | Avoid fragment roots that cause focus loss on re-render; preserve DOM identity with `key` or restore focus with `useRef` and `useEffect`. |
| RX4 | React / Next.js | Sanitize and validate injected rich HTML for heading hierarchy, alt text, and ARIA structure. |
| NG1 | Angular | Do not put `(click)` on `<div>` or `<span>` without `role`, `tabindex`, and `(keydown.enter)` / `(keydown.space)`; prefer `<button>`. |
| NG2 | Angular | Use `cdkTrapFocus` and `[cdkTrapFocusAutoCapture]="true"` for custom modal focus traps; Angular CDK `Dialog` handles focus trapping and restoration. |
| NG3 | Angular | Announce Router navigation with `LiveAnnouncer`, `NavigationEnd`, and `titleService.getTitle()` using polite announcements. |
| NG4 | Angular | Bind `[attr.aria-invalid]` and `[attr.aria-describedby]` to form control state for template-driven forms. |
| VU1 | Vue | Do not use `@click` on `<div>` or `<span>` without `role`, `tabindex`, and `@keydown`; prefer `<button>`. |
| VU2 | Vue | Manage `v-if` focus changes with `nextTick`, `ref`, and `watch`. |
| VU3 | Vue | Sanitize and validate `v-html` content for accessible structure before injection. |

## Keyboard Interaction Reference

| Key | Expected behavior |
| --- | --- |
| `Tab` | Move focus to the next focusable element in DOM order. |
| `Shift+Tab` | Move focus to the previous focusable element. |
| `Enter` | Activate buttons and links. |
| `Space` | Activate buttons, toggle checkboxes, and select radio buttons. |
| `Escape` | Close modals, dialogs, popovers, and dropdowns. |
| `Arrow Up/Down` | Navigate menus, listboxes, radio groups, and tabs as appropriate. |
| `Arrow Left/Right` | Navigate tab bars, sliders, and radio groups as appropriate. |

| `End` | Move to the last item in a list, menu, or tab bar. |

## Contrast and Layout Reference

| Element | Minimum ratio or behavior |
| --- | --- |
| Normal text below 18pt and below 14pt bold | 4.5:1 |
| Large text at least 18pt or at least 14pt bold | 3:1 |
| Incidental disabled or decorative text | No contrast requirement. |

## Good / Bad Examples

The examples below illustrate preferring native controls and preserving keyboard, name, role, and state.

**Good:**

```tsx
<button type="button" aria-label="Close dialog" onClick={onClose}>
  <svg aria-hidden="true" focusable="false" />
</button>
```

Why: The native button is keyboard-operable, has a clear accessible name, and hides the decorative SVG from assistive technology.

**Bad:**

```tsx
<div onClick={onClose}>
  <svg />
</div>
```

Why: The generic element has no role, no keyboard support, no accessible name, and no reliable state for assistive technology.

## Conventions

| Rule | Rationale |
| --- | --- |
| Target WCAG 2.2 AA for all matched UI code | It covers current WCAG 2.1 AA and 2.0 AA legal baselines while adding modern criteria. |
| Fix CRITICAL barriers before merge | Users otherwise cannot access content or complete tasks. |
| Prefer native HTML before ARIA | Native controls carry semantics, keyboard behavior, and focus behavior by default. |
| Give every interactive control an accessible name, role, value, and state | Assistive technologies need a stable control contract. |
| Keep all functionality keyboard operable with visible focus | Keyboard and switch users must be able to navigate and activate every feature. |
| Link form labels, descriptions, and errors programmatically | Users must know what each field requires and how to fix validation errors. |
| Meet text, non-text, focus, and target-size contrast requirements | Low-vision and touch users need perceivable and operable controls. |
| Provide captions, transcripts, alt text, and live regions where content requires them | Non-visual and non-audio access must be equivalent. |
| Manage route, modal, and dynamic-content focus deliberately | SPA and overlay interactions otherwise strand screen-reader and keyboard users. |

## Do / Do Not

| Do | Do not |
| --- | --- |
| Use `<button>`, `<label>`, `<nav>`, `<main>`, `<table>`, and headings semantically | Build interactive div soup and patch it with ARIA later. |
| Set `<html lang="...">` and one clear page `<h1>` with logical heading order | Omit page language or skip heading levels for visual size. |
| Use `aria-describedby`, `aria-invalid`, and a focusable error summary for invalid forms | Show errors visually without programmatic relationships. |
| Use `role="status"`, `aria-live="polite"`, or `role="alert"` for dynamic messages | Inject toasts that screen readers never announce. |
| Use `tabindex="0"` or `tabindex="-1"` only when needed | Add positive `tabindex` values. |
| Return focus after dialogs and close overlays with Escape | Trap focus or leave focus behind hidden content. |
| Respect `prefers-reduced-motion` for non-essential animation | Force motion effects on users who request less motion. |
| Provide captions for video and mute autoplaying video with controls | Autoplay audio or publish inaccessible media. |
| Sanitize and validate injected HTML for accessible structure | Trust CMS or rich-text HTML to be accessible by default. |

## Checklist Before Opening a PR

- [ ] All images have appropriate alt text, with `alt=""` for decorative images.
- [ ] Videos have synchronized captions and audio-only content has transcripts or text alternatives.
- [ ] Pages use semantic landmarks such as `<header>`, `<nav>`, `<main>`, and `<footer>`.
- [ ] Headings follow logical hierarchy with no gaps, and the page has a clear `<h1>`.
- [ ] Text contrast meets 4.5:1 for normal text and 3:1 for large text.
- [ ] UI component, graphical object, icon, and focus-indicator contrast meets 3:1.
- [ ] Information is not conveyed by color alone.
- [ ] Content reflows at 320px CSS width without horizontal reading scroll.
- [ ] `<html lang="...">` is set correctly and language changes use `lang` where needed.
- [ ] Text resizes to 200% without loss of content or functionality.
- [ ] All functionality is available from the keyboard.
- [ ] No keyboard trap exists, and Escape closes overlays unless confirmation is essential.
- [ ] A skip link is the first focusable element when repeated navigation exists.
- [ ] Visible focus indicators remain on every interactive element.
- [ ] Focus order matches meaningful visual and DOM order.
- [ ] Focus is not obscured by sticky headers, footers, or overlays.
- [ ] Focus returns to the trigger or best logical target after modal close.
- [ ] Touch targets are at least 24x24 CSS px or have equivalent spacing.
- [ ] Non-essential animation respects `prefers-reduced-motion`.
- [ ] No content flashes more than three times per second.
- [ ] Form inputs have associated `<label>`, `aria-label`, or `aria-labelledby`.
- [ ] Error messages are linked to inputs through `aria-describedby`.
- [ ] Required fields use `required` or `aria-required` and are described in text.
- [ ] Submit failures focus the first invalid field or an error summary.
- [ ] Focus and input changes do not trigger unexpected context changes.
- [ ] Interactive elements expose accessible name, role, value, and state.
- [ ] ARIA roles include required properties and use valid role names.
- [ ] No `aria-hidden="true"` content contains focusable elements.
- [ ] Dynamic content is announced through live regions.
- [ ] SPA route changes update focus or are announced to screen readers.
- [ ] Redundant ARIA is removed from native HTML elements.
