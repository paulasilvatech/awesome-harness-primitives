# Agent Customization Standards — Agents, Prompts, Instructions, and Skills

This file activates when you edit Copilot customization primitives under `.github/` or any `SKILL.md`. It defines passive schema, routing, reference, and validation conventions. It does **not** own implementation standards for files generated by those primitives; use the `github-actions`, `shell`, `terraform`, `kubernetes`, `dockerfile`, `docker-compose`, `python`, `typescript`, and `issue-forms` instructions for the underlying implementation files.

## Authoritative Sources and Precedence

Follow these sources in order:

1. `.github/docs/COPILOT-HARNESS-SPEC.md` for Copilot CLI discovery, instruction schema, agent schema, skill schema, and CLI tool vocabulary.
2. `.github/docs/templates/README.md` and the templates under `.github/docs/templates/` for repository authoring contracts.
3. This `agent-files` instruction file for passive conventions, boundaries, and focused examples.
4. Existing primitives only when they are consistent with the higher-priority sources.

When sources conflict, the higher-priority source wins. Do not copy obsolete examples from existing primitives.

## Responsibility Split

This file owns schema-safe primitive authoring conventions. Use the `validation-scripts` skill for ordered validation procedures, the domain-specific skills for operational workflows, and prompt files only for VS Code user-selected actions.

> [!IMPORTANT]
> Prompt files are a VS Code surface only. Copilot CLI discovers agents, instructions, and skills, but it does not discover or execute prompt files.

## Frontmatter Contracts

| Primitive type | Required or repo-conventional keys | Do not use |
| --- | --- | --- |
| Agent | `description`; optional verified CLI keys such as `name`, `tools`, `model`, `target`, `user-invocable`, `disable-model-invocation`, `mcp-servers`, `metadata`, `argument-hint`, and `handoffs` | Retired or unrelated keys such as `infer`, `mode`, `hidden`, `agents`, or `title` |
| Instructions | Repo convention: `applyTo` and a `Use when ...` `description`; optional `name` and `excludeAgent` | Any key outside `applyTo`, `description`, `name`, and `excludeAgent` |
| Skill | `name` and `description`; optional supported metadata such as `allowed-tools`, `argument-hint`, `license`, `metadata`, and `tags` | Top-level `version`, `category`, `authors`, or `compatibility` |
| Prompt | Baseline `name`, `description`, and useful `argument-hint`; optional VS Code `agent` and `tools` | CLI-only tool tokens or any field treated as a CLI requirement |

## Tool Vocabulary Boundaries

Agent and skill tool lists use the Copilot CLI vocabulary from the harness spec. Prompt `tools` use VS Code Configure Tools IDs and must not be copied into CLI agents or skills.

```markdown
---
description: "Use when orchestrating end-to-end Open Horizons deployment across Terraform, AKS, ArgoCD, and Backstage."
name: deploy
tools: ["read", "grep", "glob", "execute", "edit", "agent", "web_fetch", "web_search"]
user-invocable: true
---
```

```markdown
# Wrong: no-op or VS Code-only tokens in a CLI agent.
tools: ["search", "web", "todo", "search/codebase"]
```

> [!WARNING]
> Unrecognized CLI tool tokens can be silently ignored. Use `grep` and `glob` for code search, `web_fetch` or `web_search` for web access, and omit `tools` when unrestricted CLI capability is intentional.

## Instructions and Prompt Shape

Instruction files are passive rules for matching files. Keep `applyTo` as one quoted comma-separated glob string and align the scope paragraph with those globs. Include authoritative sources, a responsibility split, core conventions, a Do / Do Not table, and a verification checklist.

Prompt files are explicit VS Code actions. Keep runtime variables such as `${input:topic}` and `${selection}`, remove authoring placeholders, state precondition-failure behavior, and choose exactly one destination mode: chat response, approved workspace edit, or an exact file path.

## References and Placeholders

Reference other primitives by installed name and type, such as "Use the `terraform-cli` skill" or "use the `terraform` instructions." Do not use relative links between primitives, and do not reference a prompt from instructions intended for CLI.

Use repository-relative paths only for real files, scripts, or docs. Keep secrets, tenant-specific endpoints, private keys, tokens, and credentials out of every primitive.

## Core Conventions

| Rule | Rationale |
|---|---|
| Start routing descriptions with `Use when ...` where the schema allows it | Agents and humans need actionable activation language. |
| Keep instruction frontmatter limited to `applyTo`, `description`, `name`, and `excludeAgent` | The CLI recognizes only those keys for instructions. |
| Keep prompt `tools` absent unless exact VS Code tool IDs are verified | CLI aliases are the wrong vocabulary for VS Code prompts. |
| Put reusable ordered procedures in skills, not instructions | Instructions must remain passive and auto-applied. |
| Use installed names and primitive types for cross-primitive references | Installation paths differ across CLI, VS Code, and cloud surfaces. |
| Run the strict primitive validator after primitive changes | The validator catches schema, glob, and routing regressions. |

## Do / Do Not

| Do | Do not |
|---|---|
| Use `${input:name}` and `${selection}` in VS Code prompts | Leave template authoring placeholders in finished prompts. |
| Keep examples realistic for Open Horizons primitives | Copy obsolete examples with invalid tools or frontmatter. |
| Use the `validation-scripts` skill for validation procedures | Encode ordered setup or migration runbooks in instruction files. |
| Keep prompt files optional to CLI workflows | Make a CLI agent, skill, or instruction depend on a prompt. |

## Verification Checklist

- [ ] Frontmatter uses only fields recognized for the primitive type.
- [ ] Instruction `applyTo` globs are live and match real repository files.
- [ ] Prompt `tools` are omitted unless exact VS Code tool IDs are verified.
- [ ] Cross-primitive references use installed name and type, not relative links.
- [ ] No instruction file references a prompt as a required workflow dependency.
- [ ] Strict primitive validation passes.
